Freya TUI Implementation Plan


Executive Summary

This plan outlines the implementation of a comprehensive Terminal User Interface (TUI) for the Freya voice assistant project using the Textual framework. The TUI will provide system checks, configuration management, live chat, logging, and integration testing capabilities.



1. Current Project Analysis

1.1 Project Architecture

Agent-Based Event-Driven System:


MessageBus (Core Event System)

↓
├── DialogAgent ├── MemoryAgent ├── WakeWordAgent
├── ToolExecutorAgent
├── SpeechAgent


# LLM conversation with streaming # ChromaDB vector memory
# Background wake word detection
# 9+ tools (time, calc, files, web, etc.)
# STT/TTS coordination

└── OrchestrationCoordinator  # Lifecycle management


Key Components:
- Entry Point:   main.py - CLI argument parsing, config loading, coordinator initialization - Configuration: YAML-based ( config/default.yaml) with environment variable support - Core Infrastructure:
-   MessageBus - Async pub/sub with priority queues
-   BaseAgent - Abstract agent class with lifecycle management -   OrchestrationCoordinator - Agent orchestration layer
- Tools: 9 built-in tools (datetime, calculator, files, web search, web scraper, system, performance) - Memory: ChromaDB vector store with semantic search
- LLM: Ollama client with multi-model support (llama3.2:3b, dolphin-mixtral, deepseek-coder) - Voice: Whisper STT, Piper/ElevenLabs TTS

"""Base system check class."""

from abc import ABC, abstractmethod from dataclasses import dataclass from enum import Enum
from typing import Optional


class CheckStatus(Enum):
"""Status of a system check.""" PENDING = "pending"
RUNNING = "running" PASSED = "passed" FAILED = "failed" WARNING = "warning" SKIPPED = "skipped"


@dataclass
class CheckResult:
"""Result of a system check.""" status: CheckStatus
message: str
details: Optional[str] = None fix_suggestion: Optional[str] = None


class BaseSystemCheck(ABC):
"""Base class for system checks."""

def __init__(self, name: str, description: str, required: bool = True): self.name = name
self.description = description self.required = required self.status = CheckStatus.PENDING
self.result: Optional[CheckResult] = None

@abstractmethod
async def run(self) -> CheckResult:
"""Run the check and return result.""" pass

async def execute(self) -> CheckResult: """Execute check with error handling.""" self.status = CheckStatus.RUNNING
try:
self.result = await self.run() self.status = self.result.status return self.result
except Exception as e: self.result = CheckResult(
status=CheckStatus.FAILED, message=f"Check failed: {e}", details=str(e),
)
self.status = CheckStatus.FAILED return self.result

"""Ollama connection check."""

import httpx

from .base_check import BaseSystemCheck, CheckResult, CheckStatus


class OllamaCheck(BaseSystemCheck):
"""Check Ollama connection and models."""

def __init__(self, host: str, model: str): super().__init__(
name="Ollama Connection",
description=f"Check connection to Ollama at {host}", required=True,
)
self.host = host self.model = model

async def run(self) -> CheckResult:
"""Check Ollama connection and model availability.""" try:
# Check connection
async with httpx.AsyncClient() as client:
response = await client.get(f"{self.host}/api/tags", timeout=5.0)

if response.status_code != 200: return CheckResult(
status=CheckStatus.FAILED,
message=f"Ollama not responding (status: {response.status_code})", fix_suggestion="Ensure Ollama is running: 'ollama serve'",
)

# Check model availability
models = response.json().get("models", []) model_names = [m["name"] for m in models]

if self.model not in model_names: return CheckResult(
status=CheckStatus.WARNING, message=f"Model '{self.model}' not found",
details=f"Available models: {', '.join(model_names)}", fix_suggestion=f"Pull model: 'ollama pull {self.model}'",
)

return CheckResult( status=CheckStatus.PASSED,
message=f"Connected to Ollama, model '{self.model}' available", )

except httpx.ConnectError: return CheckResult(
status=CheckStatus.FAILED, message="Cannot connect to Ollama",
fix_suggestion="Start Ollama: 'ollama serve'", )
except Exception as e: return CheckResult(
status=CheckStatus.FAILED, message=f"Check failed: {e}",
)

4. Technical Decisions

4.1 Why Textual?

Advantages:
- Modern, actively maintained TUI framework
- Rich widget library (input, buttons, tables, trees, etc.) - CSS-like styling
- Async/await support (perfect for Freya’s event-driven architecture) - Cross-platform (Windows, Linux, macOS)
- Good documentation and examples - Mouse support
- Beautiful rendering

Alternatives Considered:
-   curses - Too low-level, complex -   urwid - Older, less maintained
-   blessed - Limited widget support
-   prompt_toolkit - More for CLI prompts than full TUI

4.5 Async Integration

Challenge: Textual runs its own async event loop, and Freya’s coordinator also uses asyncio.

Solution:
1. Run coordinator in background task
2. Use   asyncio.create_task() to run coordinator alongside Textual 3. Subscribe to MessageBus events from UI
4. Use   call_from_thread() to update UI from coordinator callbacks

Implementation:


async def on_mount(self) -> None:
"""Start coordinator when app mounts.""" # Start coordinator in background
self.coordinator_task = asyncio.create_task( self.coordinator.run()
)

# Subscribe to events self.coordinator.bus.subscribe(
"dialog.chunk", self._handle_dialog_chunk
)

8. Troubleshooting Guide

8.1 Common Issues

Issue: Textual app won’t start - Check Python version (3.11+)
- Verify Textual installation:   pip show textual - Check terminal compatibility

Issue: Coordinator not responding in UI - Verify MessageBus is started
- Check event subscriptions - Enable debug logging

Issue: UI freezes during LLM response - Ensure coordinator runs in separate task
- Use   asyncio.create_task() for long operations - Don’t block UI thread

Issue: Chat messages not appearing - Verify MessageBus subscriptions
- Check topic names match - Enable event logging
